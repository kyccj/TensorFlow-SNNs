## 0. 정의와 fan-out 검산

- **스파이킹 층**: n_in (아날로그 직접 입력, `input_spike_mode=REAL`) 과 predictions_n (막전위를 내는 출력 적분기) 을 뺀 18층. 뉴런 N = 7·(32·32·128) + 6·(16·16·256) + 4·(8·8·512) + 256 = **1,442,048**.
- **FR** = S / (N·T): 뉴런당 스텝당 스파이크 (S = 이미지당 스파이크, T=4 합). **FR_T** = S / N. AP (원문 4.1절 식: 테스트 샘플·뉴런·스텝 전체의 평균) 와 UniSparse (코드 `us_main.py` 465–522행: 각 뉴런층의 (x≠0) 평균을 원소 수로 가중) 둘 다 이 전체 FR 정의와 같은 꼴임을 확인했다. UniSparse 의 FR 에는 출력 앞 LIF 가 빠진다 (SparseNeuron 만 감시). 층마다 FR 을 내고 층을 같은 무게로 평균하면 값이 작아진다 (baseline 0.0719 대 전체 0.0879, n=3, −18%).
- **SOPs** = Σ_층 Σ_위치 (그 위치의 스파이크 수, 채널 합) × fan-out(위치). fan-out = 그 뉴런 스파이크 하나가 다음 가중치 층에서 일으키는 누산 수 (패딩 0 은 세지 않음). 이미지당, T 합. UPR·UniSparse 의 SOPs 정의와 같은 꼴이다. UniSparse 코드 (`SOPMonitor`) 는 입력 스파이크를 1 로 채운 마스크 커널로 conv2d 해 합하므로 패딩을 세지 않는 점도 같다. 다만 conv 층만 세고 첫 conv 를 빼며, SEW 덧셈 뒤의 정수 입력 (예: 2) 을 값만큼 센다.
  - 주 규약: BN 은 앞 conv 에 접힘 (0). identity shortcut 의 Add 는 0. 단계 입구 1×1 shortcut (conv0) 은 셈. GAP 는 fc1 에 접음 (conv4_block2_out_n 스파이크 하나 → fc1 256 누산). fc1_n → predictions 10. predictions_n → 0. 이진 스파이크가 일으키므로 모두 AC (누산) 다 (스텝별 배열의 원소 최대값이 n_samples 이하라 이진임을 확인).

- **첫 층 (직접 입력)**: conv1_conv 는 실수 입력을 받으므로 MAC 이다. 입력이 네 스텝 모두 **원소 단위로 같다** (`n_in__t`, 스텝별 배열이 있는 npz 24/24개). 밀집 MAC 은 패딩 포함 32·32·128·(3·3·3) = 3,538,944/스텝 (thop 식; UniSparse·AP 코드가 MACs 를 세는 규약과 같다), 패딩을 빼면 94·94·3·128 = 3,393,024 (−4.1%) 다. 즉 SOPs (패딩 제외) 와 첫 층 MAC (패딩 포함) 은 규약이 다르다. 이 문서는 패딩 포함 값을 쓴다. 매 스텝 다시 계산하면 14,155,776, 한 번만 계산하면 3,538,944 이다. 방법과 무관하고 SOPs (AC) 에는 넣지 않는다.
- **밀집 동등**: 모든 뉴런이 매 스텝 쏘면 SOPs 는 2.126G/스텝이다. baseline 의 SOPs 는 그 7.7%, ours 는 5.8%.

**fan-out 출처와 검산 (다섯 겹)**

1. 구조는 `models/resnet.py` 를 읽어 만들었다: ResNet19 = 초기 128채널, 블록 [3,3,2], block_basic (conv1 3×3 stride same → BN → conv1_n → conv2 3×3 same → BN → Add → out_n, sew=False), 각 단계 block1 만 1×1 conv0 shortcut (lib_snn Conv2D 기본 padding='valid'), conv2 단계 stride 1·나머지 stride 2, GAP → fc1 Dense(256) → fc1_n → predictions Dense(10).
2. 실제 Keras 그래프 (`analysis/prune_measure.py` 가 체크포인트를 올려 뽑은 가중치 층 22개: 이름·커널 모양·출력 위치 수·src/dst 스파이킹 층) 와 **일치 (22개 모두)** (`r19c10-bpsr-6e-10-s1.json`).
3. 기존 `analysis/r19_fanout.py` (10-09 SynOps 분석에 쓴 것) 의 지도와 **모든 층에서 같다**. baseline SOPs/스파이크 1286.1 (n=3) 는 10-09 보고 1,286.1 과 같다.
4. TF (CPU) 로 패딩 규칙을 독립 검산했다: d Σ conv2d(x, 1) / dx = 그 입력을 읽는 출력 위치 수. 3×3 s1/s2 SAME (32, 16, 8), 1×1 s2 VALID 여섯 경우 모두 최대 차 0.
5. SOPs 자체도 다른 경로로 다시 셌다: 실제 Keras 가중치 층 목록을 따라 각 층 입력의 위치별 스파이크 지도를 TF conv2d (커널 전부 1) 에 통과시킨 합 × C_out. 4런 (base---s11, ours_ch-3e-3-s4, bpsr-1e-10-s1, l2-1e-7-s3) 에서 상대 차 최대 0.0e+00. (eip-critic 이 numpy 로 따로 짠 fan-out 으로도 15런 모두 같았다.)

## 3. baseline 대비 감소 (세 측정 축)

- 칸 = 100·(묶음 평균 / baseline 평균 − 1) [95% CI]. CI 는 두 묶음의 시드 산포를 ln 비의 델타법으로 함께 전파했다 (Welch 자유도). npz 계열 열의 baseline 은 npz n=3 (138 서버만), s_count 열의 baseline 은 원장 n=6.
- "SOPs/스파이크 감소비" = SOPs 감소율 / npz 스파이크 감소율. 1 보다 작으면 SOPs 가 스파이크보다 덜 준다. CI 없는 기술값이고 감소 깊이에 따라 변한다 (4절 탄력성 0.84 → 깊이 줄일수록 비가 변함). 팔 사이 0.01 안팎의 차는 해석하지 않는다.
- Δacc = 묶음 − baseline (원장 best val acc, n=6), Welch 95% CI.

CI 에 들어가지 않은 약 1%p 의 편향이고 방향은 보수적이다 (우리 감소를 작게 보이게 함). 논문에 쓴다면 "SOPs −24% (npz 축, baseline n=3, 138 서버만)" 처럼 범위를 붙인다. baseline s14~s16 npz 를 추출하면 풀린다 (GPU 승인).
- `- vmem` 은 같은 착지를 노렸지만 실제로는 스파이크가 더 남았다 (npz −22.5%, n=4). 그래서 SOPs 도 덜 줄었다. 정확도 Δ 는 이 표가 아니라 `ablation_261019.md` 의 같은 스파이크 비교로 읽는다.

## 6. SOPs 축에서 우리가 약해 보이는 곳

1. **학습 없이 추론 T 를 한 스텝 줄이고 BN 이동통계만 다시 잡은 baseline 이 스파이크·SOPs 로는 ours 보다 깊다 (10-20 정정).** 실측 (CPU, 테스트 앞 1000장, 체크포인트 n=3, 138): 스파이크 -39.0% [-39.9, -38.1], SOPs 추정 -39.3% [-40.0, -38.6], 자기 T=4 대비 -0.17%p [-1.23, +0.90]. 같은 1000장에서 ours 3e-3 T=4 는 스파이크 -27.8%, SOPs 추정 -24.3% (n=3 대 3) 다. 정확도 손실은 ±0.2%p 마진 판정을 못 한다. BN 을 T=4 값으로 두면 -3.37%p [-4.90, -1.90] 라 이 대조는 'BN 재추정' 조건이 붙어야 성립한다. compare-candidates 체크리스트의 "더 센 상대" (SEENN·DT-SNN 계열의 가장 단순한 형태) 후보가 우리 체크포인트 안에 있다. 단서: T' 사후 선택, T=4 기준 best 에폭 (낙관적), 138 n=3, 1000장. 검토 전 판의 "T=3 Δ -0.02 [-0.10, +0.06], 스파이크 -38.3%" 와 "ours 를 T=3 에서 끊으면 Δ -0.16 [-0.38, +0.07]" 는 비인과 판독이라 인용하지 않는다. 판정에는 1만 장 재측정이 필요하다 (early_exit_261020 8절).
2. **헤드라인 −30% 가 SOPs 로는 −24% 다.** s_count -30.1% (n=4 대 6) → npz 스파이크 -27.4% → SOPs -23.8% (n=4 대 3) → 에너지 추정 -21.4%. 측정 축을 바꿀 때마다 작아진다. npz 축 baseline 은 138 서버 n=3 뿐이고, n=6 으로 외삽하면 npz 감소는 -28.5% 다 (3절).
3. **SOPs 깊이로 방법 순위를 말할 수 없다.** 표1 점에서는 BPSR 1e-10 (-27.5%) 이 ours 3e-3 (-23.8%) 보다 깊고, 동등성 최심점에서는 ours 4e-3 (-31.2%, n=3) 이 BPSR 1e-10 보다 깊다. 둘 다 착지 선택이다. plain L2 1.5e-7 은 npz 가 없다.
4. **경쟁 가중이 SOPs 를 따로 줄이지 않는다.** 같은 스파이크 SOPs 차가 1% 미만이고 (npz 축 n=29·25 에서 0 포함, s_count 축 plain L2 대비 +0.50% 는 ours 가 더 쓰는 방향), 감소가 fan-out 이 작은 32×32 층에 몰리는 것도 BPSR·plain L2 와 같다. "에너지에 맞춘 규제" 라고 쓸 근거가 없다 (Suetake·Sorbaro·UniSparse 는 fan-out 으로 가중한다).
5. **가중치 프루닝과 결합한 행에는 절대 SOPs 로 한 자릿수 이상 진다.** UniSparse SEW-R19 C10 T=4 는 94.71% 에서 39.47M, 91.56% 에서 6.11M (n=3) 이고 ours 는 497M 이다 (12.6배). 그러나 밀집끼리는 우리 baseline 이 UniSparse 밀집보다 작고 (0.71배), 이 차는 모델이 아니라 프루닝에서 온다 (5절). Activity Pruning R20 C10 은 92.05% 에서 61.70M (8.1배) 이지만 밀집 256.69M 의 작은 모델이다.
6. **감소 깊이가 얕은 쪽이다.** 정확도 손실 0.25%p 이내 행끼리 SOPs (또는 같은 꼴 지표) 감소: UPR −95.1% (C10 6Conv T=8, 프루닝), Sorbaro −26.9% (변환 SNN), 우리 −23.8% (n=4). 손실을 0.5~1%p 안팎까지 허용하면 UniSparse −95.7% (−0.45%p, 프루닝 결합, FR 은 −19.2%), Activity Pruning −76.0% (−0.84%p), Spik4lite −60.9% (−1.09%p). 우리는 s_count 축 −47~−51% 부터 손실이 시작된다 (CC 0절, n=3).
7. **첫 층 MAC 이 고정 비용으로 남는다.** 직접 입력이라 conv1 이 이미지당 14.16M MAC (매 스텝 계산 시, 패딩 포함) 이고, 에너지 추정에서 몫이 baseline 10.0% → ours 12.7% 로 커진다. 스파이크 규제로는 줄일 수 없다. 입력이 스텝마다 같으므로 한 번만 계산하는 구현을 전제하면 이 몫은 1/4 이 된다 (그때 에너지 추정 -23.2% [-25.1, -21.2]).
8. **FR 절대값도 유리하지 않다.** ours 의 FR 0.0639 (n=4) 는 Activity Pruning R20 의 무손실에 가장 가까운 행 0.053 과 UniSparse λ 5e-7 점 0.0552 (n=3) 보다 높다 (UniSparse 밀집 0.0683 보다는 낮고, 우리 baseline 0.0879 은 그보다 높다). 모델·구현이 달라 FR 절대값끼리는 판정하지 않는다.
9. **절대 FR·SOPs 는 09-15 보류에 걸린다.** npz 절대값 자체이므로 보류가 풀리기 전에는 논문 표에 넣지 않는다 (머리말).

**우리 쪽에 남는 것 (과장하지 않음)**: 정확도 손실이 검출되지 않는 구간 (Δ −0.01 [−0.18, +0.17], n=4 대 6) 에서의 SOPs −24% 이고, baseline 정확도가 문헌 행보다 높다 (96.73, n=6). 밀집 SOPs 도 같은 이름의 UniSparse 모델보다 작다. 그러나 같은 구간에서 BPSR·plain L2 도 같은 크기의 SOPs 감소를 내고, 학습 없이 추론 T 를 한 스텝 줄이고 BN 이동통계만 다시 잡은 baseline 이 스파이크·SOPs 로는 더 깊다 (정확도 손실은 판정 못 함, 1000장 n=3, 3b 절).

## [LIMITATION]

- **절대 FR·SOPs 는 09-15 보류 (s_count 와 npz 11% 불일치, 원인 미상) 에 걸린다.** npz/s_count 비가 팔마다 다르다 (baseline 1.053, ours 1.077). 원인을 밝히거나 사용자가 측정 축을 정하기 전에는 논문에 쓰지 않는다.
- **문헌 행은 어느 것도 엄밀하게 비교할 수 없다.** 모델·T·레시피·baseline 정확도·FR/SOPs 의 층 포함 범위 (입력층·출력층·shortcut·GAP) 가 다르고, 대부분 n 을 적지 않았다. UniSparse 는 코드로 정의를 확인했지만 SEW 덧셈의 정수 입력과 가중치 프루닝이 섞여 스파이크만의 SOPs 감소는 분리되지 않는다. 감소율 (%) 끼리만 참고로 놓았고, "이긴다·진다" 는 문헌 행과의 판정으로 쓰지 않는다.
- STDS 는 AP 의 재구현값이고 원문 표는 읽지 않았다. ESL-SNN 표 값은 미확인이다. SRSC 는 초록뿐이고 심사 중이다. MI-TRQR·DSN 은 범위 값만 있다. DT-SNN·Sorbaro 는 RA 값을 이번에 다시 확인하지 않았다.
- **refs-audit 정정 필요 (eip-refs 에 넘김, 이 문서에서는 고치지 않음).** `docs/paper/refs-audit.md` 821·830·842행 부근의 "UniSparse 밀집 행 없음" 은 틀렸다 — 부록 Table 4 에 R19 C10 밀집 95.16 ±0.03 @923.01M, FR 6.83% (n=3) 와 ImageNet R18 밀집 63.78 @1545.91M 이 있다.
- **npz 축 baseline 은 n=3 (138 서버만)** 이다. 원장 baseline 은 n=6. 23 서버 baseline 의 s_count 가 +3.2% (검출 안 됨) 라 npz 계열 감소율에 약 1%p 의 보수적 편향이 있을 수 있다 (3절). 규제 팔은 138·23 이 섞였다.
- **추론 T 감소 (3b) 는 CPU 1000장 × 팔당 체크포인트 3개 (138) 의 실측이다** (10-20 정정 전에는 npz 비인과 판독을 썼다). T' 를 사후에 골랐고, best 에폭 선택이 T=4 테스트 정확도에 맞춰져 있다. BN 재추정 T'=3 의 정확도 손실은 이원 부트스트랩 구간 폭이 약 2%p 라 정해지지 않았고, 재추정 데이터 (증강 유무) 에 1%p 안팎 민감하다. SOPs·에너지는 층별 추정이다. 이 망 (시간 평균 BN) 의 샘플별 조기 종료는 npz 로 모의할 수 없다 (early_exit_261020).
- 같은 스파이크 SOPs 곡선은 서버 항만 넣었고 실행 시기 (9월/10월) 항은 넣지 않았다. plain L2 는 s_count 322–394K 에만 있어 200–420K 비교는 공통 기울기에 기댄다. 스텝별 값은 스텝별 배열이 있는 npz 만이라 BPSR n=1, plain L2 n=2 로 판단하지 않는다.
- SOPs 는 연산 수 프록시다. 메모리 접근, 막전위 갱신·누설, 편향 덧셈, 희소 데이터 이동 비용은 넣지 않았다. 에너지 추정 (0.9/4.6 pJ, 45nm FP32 값) 도 같은 한계를 가진다. 실측 (Speck·Jetson) 과의 관계는 이 분석이 말할 수 없다.
- 정확도 비교는 이 분석의 범위가 아니다. Δacc 는 원장 best val acc (테스트 셋에서 고른 최고값, 낙관적) 의 Welch 이고, 비열등 판정은 `method_261019.md`·`results_261019.md` 를 따른다.
- C100·VGGSNN·QKFormer·SDTv3 는 계산하지 않았다 (R19 C100 npz 없음). 문헌 비교표는 R19 C10 한 설정의 값이다.

**다음 (GPU 또는 긴 CPU 계산이라 모두 승인 필요, 제안만)**: (1) 같은 체크포인트로 s_count 코드 경로와 npz 를 대조해 09-15 보류의 원인 확인. (2) baseline s14~s16 npz 추출 (n=6, 서버 균형). (3) plain L2 1.5e-7 s1~s3 npz 추출 (동등성 최심점 비교 완성). (4) T'=3 + BN 재추정 대조를 테스트 1만 장으로 다시 잰다 (early_exit_261020 8절 첫 제안; 가중치를 바꾸지 않는 추론). 검토 전 판의 (4) "샘플별 스텝별 스파이크 재추출 (SEENN 식 조기 종료 모의용)" 은 10-20 정정으로 뺐다 — 시간 평균 BN 망에서는 그 배열로도 조기 종료를 모의할 수 없다.
