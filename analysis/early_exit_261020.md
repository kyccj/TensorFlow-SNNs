## 한 줄

**npz 의 스텝별 출력으로는 조기 종료를 모의할 수 없다.** R19 의 BN 이 T 스텝 입력의 시간 평균에 걸려 망이 시간에 인과적이지 않다. 스텝 t 출력은 스텝 t 에서 계산을 멈춘 출력이 아니고, 4스텝을 다 돈 뒤 일찍 읽는 용도로만 쓸 수 있다. 그렇게 읽는 조기 종료가 아낄 수 있는 스파이크는 마지막 BN 뒤 두 층의 뒤 스텝뿐이라 **최대 0.82 ±0.01% (baseline n=3; 시간 평균 BN 망, 18층 npz 스파이크 기준)** 다. T 를 실제로 줄여 다시 돌리는 것은 BN 을 어떻게 두느냐에 달렸다 (아래 [ ] 는 체크포인트×이미지 이원 부트스트랩 95%, 팔당 체크포인트 3개 × 1000장). **T=4 BN 이동통계를 그대로 두면** T'=3 이 자기 T=4 대비 baseline -3.37%p [-4.90, -1.90], ours_inter_ch -3.80%p [-5.13, -2.50] 이고 T'=2 는 우연 수준 (8.5~12.0%, 200장 × 체크포인트 3개) 이다.
**BN 이동통계만 T' 에서 다시 잡으면** (학습셋 5000장을 학습 후반과 같은 증강으로 순전파, 가중치 그대로) T'=3 은 자기 원래 T=4 대비 baseline -0.17%p [-1.23, +0.90], ours_inter_ch -0.67%p [-1.47, +0.10] 이고, 스파이크는 baseline -39.0 ±0.3%, ours -40.4 ±0.4% (원래 T=4 대비, 같은 1000장) 다. BN 고정 손실 (baseline -3.37, ours -3.80%p) 의 대부분은 BN 이동통계 불일치였고, 남은 손실은 이 규모로 ±0.2%p 마진 판정을 못 한다. **그래서 '학습 없이 T 를 한 스텝 줄이고 BN 만 다시 잡은 baseline' 은 스파이크 -39% 로 ours_inter_ch T=4 (-27.8%, npz 축) 보다 깊은 학습 없는 대조가 될 수 있다** (정확도 손실이 마진 안이라는 근거도 밖이라는 근거도 아직 없음, 8절). T'=2 는 BN 을 다시 잡아도 정확도 50.7~66.9% 로 무너진다 (체크포인트 6개). 검토 전 판의 "재학습 없는 T 감소는 쓸 수 없다" 는 BN 고정 조건에서만 맞는 말이다.
(a) T=4 를 끝까지 도는 지금 망에서는 조기 종료만으로 ours_inter_ch 의 감소 (npz 축 -27.8%, s_count 축 -29.4%, n=3 대 3) 에 닿지 않는다. (b) 같은 조건에서 ours 에 걸어도 1% 미만만 더해진다. 인과적 망의 조기 종료 위에 ours 가 쌓이는지는 이 분석이 말하지 못한다. (c) SEENN-I 는 스텝마다 CE 를 거는 학습과 멈춘 스텝까지만 계산하는 망을 전제해 우리 판독과 같은 축에 놓을 수 없다. 스파이크 축 비교에는 학습이 필요하다 (8절).

## 0. 왜 스텝별 출력을 그대로 쓸 수 없나

- 구조: R19 의 각 conv 층은 `Conv → BN → 뉴런` 이다 (`models/resnet.py` block_basic 88~100행, 첫 층 330~334행). BN 노드는 시간 루프에서 `f_temporal_reduction` 분기를 탄다 (`lib_snn/model.py` 3459~3505행, `_run_internal_graph_snn_t_first_k2`; `snn_training_spatial_first=False` 가 기본이라 학습·추론 모두 이 경로; 결정 기록 10-15 항목 (3) 도 같은 경로를 실제 경로로 적음). 입력의 T 스텝 평균 한 장에 BN 을 걸고, 그 결과를 모든 스텝에 복사한다. `flags.py` 의 `bn_per_step` 주석 (10-15)이 같은 내용이다. `bn_per_step` 은 기본 False 이고 VGGSNN × CIFAR10-DVS 전용이다.
- 결과: conv1 (입력이 정적 이미지라 상관없음) 다음 층부터는 스텝 1 의 입력 전류가 앞 층 스텝 1~4 발화의 평균이다. T=4 런의 스텝 t 출력에는 이미 스텝 t+1~4 의 정보가 들어 있다.
- 출력: 출력층은 누설 없는 적분기다 (`layers.py` 198행 n_type=OUT, `neurons.py` 3073~3087행). 모델 출력은 마지막 스텝 막전위다 (`last_ts`). 점검: npz 의 `logits == logits_t[:, 3]` 이 6런 모두 최대 차 0 이다. 그래서 SEENN-I 의 "누적 출력 평균" 은 `logits_t[:, t] / t` 로 잡았다 (argmax 는 같고, 신뢰도 크기만 다르다). 막전위를 그대로 쓴 민감도 판도 JSON `curve_raw_cs` 에 있다.
- **그래서 스텝 t 출력은 스텝 t 에서 계산을 멈춘 출력이 아니다. 몸통 (마지막 BN 까지) 을 4스텝 다 돈 뒤 출력을 일찍 읽는 용도로만 쓸 수 있다.** 3절의 '실현 가능한 조기 종료' 는 이 읽기다.
- **직접 확인 (CPU, 6절)**: 같은 체크포인트를 T'=1·2·3 으로 다시 돌린 결과를 T=4 런의 앞 T' 스텝과 비교했다. 근거 규모는 체크포인트 3개 × 200장 (T'=1·2·3) 과 체크포인트 6개 × 1000장 (T'=3) 이다. 200장 비교 (체크포인트 3개 × T'=1·2·3) 에서 conv1 발화는 모두 비트 단위로 같았다. 1000장 T'=3 비교에서는 체크포인트 5개가 비트 단위로 같았고, r19c10-ours_ch-3e-3-s2 는 3000 (이미지, 스텝) 칸 중 1칸에서 합 1 스파이크 차 (CPU 부동소수 차 수준). 반면 conv2_block1_conv1_n 은 칸의 99~100% 가 다르고, 칸당 평균 절대 차가 그 층 스파이크의 4.8~8.0% 다 (체크포인트 6개). 처음 달라지는 층 (칸의 1% 넘게 다름) 은 conv2_block1_conv1_n 이다. 아래 표는 BN 이동통계를 T=4 값 그대로 둔 결과다 (BN 을 다시 잡은 결과는 6.2절).

## 4. 질문별 답

**(a) 조기 종료만으로 baseline 정확도에서 ours_inter_ch 만큼 줄어드나? — T=4 를 끝까지 도는 지금 망에서는 아니다.** 실현 가능한 조기 종료의 절감은 손실 0 에서 0.69 ±0.03%, 손실 0.10%p 허용에서 0.70 ±0.03%, 상한 0.82 ±0.01% 다 (모두 baseline n=3, 시간 평균 BN 망, 18층 npz 스파이크). ours_inter_ch 3e-3 은 npz 축 -27.8% [-30.4, -25.1], s_count 축 -29.4% [-32.5, -26.1] (n=3 대 3) 다. T 를 실제로 줄여 다시 돌리는 것은 조기 종료가 아니라 '모든 이미지 같은 T' 이고, 결과는 BN 처리에 달렸다 (6절).

**(b) ours 위에 조기 종료가 더해지나? — T=4 를 끝까지 도는 지금 망에서는 1% 미만이다** (ours 상한 1.07 ±0.03%, n=3). 각 팔의 T=4 정확도에서 손실 0 으로 맞추면 ours+조기 종료 / baseline+조기 종료 스파이크는 -27.9% [-30.5, -25.2] (n=3 대 3)다. - 방법 (precise BN): T' 로 만든 모델에 학습셋 앞 이미지를 흘린다. 이 동안 각 BN 은 그 배치의 통계로 정규화하고, 배치 평균 m_b·분산 v_b 를 모아 모집단 평균 = mean(m_b), 분산 = mean(v_b) + var(m_b) 로 이동통계를 바꾼다 (BN 20층). 정규화 식은 원래 코드 경로 그대로다. 테스트 전처리는 test_ds 첫 배치와 최대 차 0 으로 대조했다. 체크포인트 파일에는 쓰지 않았다. 평가는 테스트 앞 1000장 (6.1 과 같은 이미지) 이다.

## 7. 다른 문서에 대한 함의 (이 문서는 고치지 않음, 각 담당이 고칠 것)

- compare-candidates 1.1 의 "우리 baseline 은 스텝 1 의 스파이크 몫이 3.7% 라서 일찍 끝내면 스파이크가 크게 줄 수 있다" 는 지금 망에 맞지 않는다. 스텝 1 의 발화도 스텝 2~4 를 다 돌아야 계산된다.
- 1.2 의 3번 (시간축 대조, T=2·T=1 학습) 은 그대로 유효하다. 그 T 로 학습하면 BN 평균도 그 T 위에서 잡힌다. 다만 검토 전 판의 "재학습 없는 T 감소는 쓸 수 없다" 는 뺐다. BN 이동통계만 다시 잡으면 baseline T'=3 이 원래 T=4 대비 -0.17%p [-1.23, +0.90] (이원 부트스트랩), 스파이크 -39.0 ±0.3% 다 (6.2절, 증강판, 체크포인트 3개 × 1000장). 학습 없는 대조 (T 감소 + BN 재추정) 를 시간축 대조에 넣을지는 사용자가 정한다 (8절).
- 3.5 판정표의 "조기 종료 모의가 0.1pp 이하 손실로 −30% 를 넘김" 행은 npz 판독으로는 판정할 수 없다. 모의가 성립하지 않아서이지, SEENN 류가 진다는 근거가 아니다. 가장 가까운 실측은 6.2 의 'T'=3 + BN 재추정' 이고, 스파이크는 −30% 를 넘지만 정확도 손실이 0.1%p 이하인지는 1000장 × 체크포인트 3개로 판정할 수 없다 (8절 첫 제안).
- **같은 오해 (`logits_t[:, t]` = 't 스텝에서 멈춘 출력') 가 다른 문서 5곳에 있다.** 숫자 자체는 판독값으로 맞지만, '추론을 t 스텝에서 끊으면' 으로 읽은 결론은 6절 결과와 충돌한다.
  - `analysis/fr_sops_261020.md` 3b절·요약 3번·5절 'baseline, 추론 T=3' 행·6절 1번: "스텝 t 까지의 계산은 뒤 스텝과 무관하므로 … 정확히 얻는다 (모의가 아님)" 와 "추론만 한 스텝 일찍 끊은 baseline 이 ours 보다 깊다 (T=3 Δ -0.02, 스파이크 -38.3%)". ## 8. 제안 (실행 안 함, 사용자 결정)

- SEENN 식 비교 (인과적 망 + 스텝별 학습) 를 스파이크 축으로 하려면 학습이 필요하다. 길은 두 가지다.
  - (1) TF, 같은 레시피: `bn_per_step` 을 R19 로 넓히고 (지금은 VGGSNN × DVS 밖에서 켜면 model_builder 가 멈춤), **스텝별 CE (TET) 손실을 새로 구현**한 뒤 학습한다. TF 에는 TET 손실 플래그가 없다 (`snn_out_proc='all'` 로 스텝별 출력을 꺼낼 수만 있음). 학습 경로 변경이라 연기시험과 배포 승인이 필요하다 (3등급).
  - (2) 별도 env·폴더: 공개 SEENN PyTorch 코드 (github.com/Intelligent-Computing-Lab-Yale/SEENN, TET 틀) 로 R19 C10 을 돌리고 스파이크를 센다. TF 학습 경로를 건드리지 않는다 (CLAUDE.md 가 Codex 에 맡길 일로 둔 'PyTorch 재현'). 프레임워크·레시피 차이 (뉴런 τ·리셋, 옵티마이저, 증강) 를 함께 적어야 한다.
- **(먼저 권함, 사용자 확인 필요) T 감소 + BN 재추정 대조를 1만 장으로.** 6.2 에서 baseline T'=3 + BN 재추정이 스파이크 −39% 에 정확도 손실을 가리지 못하는 대조로 나왔다. 논문 주장 (같은 정확도에서 스파이크 감소) 에 가장 직접적인 위협이라, 테스트 1만 장 × 팔당 체크포인트 3개 (baseline s11~s13, ours 3e-3 s2~s4) 로 T'=3 을 다시 잰다 (T'=2 는 BN 을 다시 잡아도 무너져 뺀다). 가중치를 바꾸지 않는 추론이라 학습 경로·큐와 무관하다. CPU 로 체크포인트·T' 하나에 약 20~40분 (추정: 5000장 추정 + 1만 장 평가, 이번 1000장 실측이 다른 작업과 겹쳐 10~12분) 이고, GPU 를 쓰면 짧아지지만 GPU 사용은 확인이 필요하다. 추정 장 수 (5000 → 1만) 와 난수를 바꾼 민감도도 함께 잰다.
- 위 대조와 함께 T=2/T=3 으로 학습한 baseline (compare-candidates 1.2 의 3번) 을 두어야 'T 만 줄이면 되지 않나' 에 대한 답이 완성된다. BN 재추정만 있으면 학습 대조가 없다는 지적, 학습 대조만 있으면 학습 없는 대조를 빠뜨렸다는 지적을 받는다.

## [LIMITATION]

- **이 분석은 SEENN 류 (스텝별 학습 + 인과적 망)가 우리 R19 C10 에서 스파이크 축으로 ours_inter_ch 를 앞서는지 말할 수 없다.** 학습이 필요하다 (8절의 두 길).
- 3절의 판독·조기 종료 정확도는 실현 가능한 읽기다 (몸통 4스텝을 다 돈 뒤 출력만 일찍 읽음). 그때의 "평균 T" 는 계산 시간이 아니다.
- 실현 스파이크 회계는 꼬리 층의 스텝별 발화를 이미지와 무관한 테스트셋 평균으로 근사했다. 꼬리 층이 전체의 0.86~1.16% 라 결론에는 영향이 없다. 스파이크는 18층 npz 수이고 계산량·지연이 아니다.
- npz 런: 스텝별 배열이 있는 baseline s11~s13 과 ours 3e-3 s2~s4 만 썼다 (각 n=3, 학습 서버 138, npz 추출 기계는 canus 와 55 서버). 원장 전체 (baseline n=6, ours n=4) 로는 재지 않았다. 서버 23 런은 포함되지 않았다.
- CPU 점검: 200장 표는 체크포인트 3개, T'=3 과 BN 재추정은 체크포인트 6개 (팔당 3개) × 1000장이다. 정확도 차의 체크포인트 수준 구간은 df=2 라 넓다. 팔 간 차는 판단하지 않는다.
- **학습 없는 T 감소 (T'=3 + BN 재추정) 의 정확도 손실은 이 분석으로 정해지지 않았다.** 1000장 × 팔당 체크포인트 3개라 이원 부트스트랩 구간이 약 2%p 폭이다. 0 인지 0.5~1%p 인지에 따라 ours 와의 비교 결론이 바뀐다 (8절 첫 제안).
- BN 재추정은 두 설정 (증강 5000장, 무증강 3000장) 만 했다. 장 수·난수를 바꾼 민감도는 재지 않았다. 절반 표본 대비 통계 차는 JSON `recal.*.runs.*.T.*.conv_half_vs_full_*` 에 있다. 평가는 1000장이라 체크포인트당 정확도 차의 표준오차가 약 0.3~0.7%p 다.
- τ 는 테스트셋에서 골랐다. val = test 라 고를 데이터가 따로 없다.
- 2절의 같은 스파이크 대조군 비교는 n 이 1~4 이고 ANCOVA 를 하지 않은 서술이다.
- SEENN 수치는 arXiv v2 PDF 에서 직접 읽었다. NeurIPS proceedings 판과 대조하지 않았다. SEENN 코드의 BN 구현은 읽지 않았다. "인과적 망" 은 평균 T 를 비용으로 셌다는 점에서 추론한 것이다.
