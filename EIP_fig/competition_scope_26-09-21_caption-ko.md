## 2026-09-21 수정 내역 (사용자 피드백 반영)

1. **글자색 자동 반전** — 이전에는 `sc_rate>0.55` 고정 임계로 글자색을 정해 남색 칸(낮은
   `sc_rate`)의 숫자가 안 보였다. 이제 각 칸의 실제 컬러맵 RGB에서 상대 휘도
   (`0.299R+0.587G+0.114B`)를 계산해 0.5 미만이면 흰 글자, 이상이면 검은 글자를 쓴다.
   눈으로 확인: 남색(`sc_rate=0` 근방) 칸은 전부 흰 숫자, 연노랑(`sc_rate=1` 근방) 칸은
   검은 숫자로 바뀌었다.
2. **이름 교체** — 플래그 내부값 대신 팔 이름을 병기했다. 채널 **안**에서 겨루는 게
   `intra`, 채널**끼리** 겨루는 게 `inter` 다.
3. **예시 맵 재설계 + 차이 표시** — 채널 간 최고값 격차를 키움(A=4, B=2, C=1). `none`
   (`ours_layer`) 패널에는 `within_channel`(`ours_intra_ch`) 대비 값이 달라진 칸에 주황
   삼각형을 표시(8/48칸). `channel`(`ours_inter_ch`) 패널은 채널 전체가 균일값이 되어
   48칸 전부가 다르므로, 칸별 표시 대신 문구로 대신했다 — 이유는 아래 "표시 방식 선택".

## 코드 플래그 ↔ 그림 이름 대응

| 코드 플래그 (`reg_spike_maxnorm_group`) | 그림 이름 | 경쟁 범위 |
|---|---|---|
| `within_channel` | `ours_intra_ch` | 채널마다 따로 최댓값 (per-channel) |
| `none` | `ours_layer` | 층 전체 하나의 최댓값 (layer-wide) |
| `channel` | `ours_inter_ch` | 채널 공간합끼리 경쟁 후 broadcast (channel-sum) |

## 캡션 본문

`reg_spike_maxnorm_group` 이 결정하는 경쟁 범위 3종. 같은 예시 spike map(4×4 특징맵,
채널 3개, T=4, 숫자는 illustrative — 실험값 아님, 채널 간 최고값 A=4/B=2/C=1) 위에서
`sc_norm = spike_count / max(그룹)` 의 "그룹"만 다르게 잡고, `sc_rate = 1 − β·sc_norm`
(β=1.0, `1-maxnorm`) 을 계산했다.

- **`ours_intra_ch`** (`within_channel`): 채널마다 따로 최댓값을 잡는다. 세 채널 모두
  자기 채널 안의 1등이 `sc_rate=0`(보호)을 받는다 — 주황 테두리가 A·B·C 세 채널
  전부에 하나씩 있다.
- **`ours_layer`** (`none`): 층 전체에서 하나의 최댓값만 쓴다. 채널 A의 4가 유일한
  층 전체 1등이라 그것만 주황 테두리로 보호받고, 채널 B·C는 자기 채널 안의 1등이라도
  전혀 보호받지 못한다(주황 테두리 없음) — 약한 채널이 통째로 눌린다. `ours_intra_ch`
  대비 달라진 칸은 주황 삼각형으로 표시했다(8/48칸, 모두 채널 B·C에서 발생).
- **`ours_inter_ch`** (`channel`): 채널의 공간 합(`ch=Σ_{h,w} spike`)끼리 경쟁하고, 이긴
  채널의 비율을 그 채널 안 **모든 위치에 그대로 broadcast** 한다. 채널 A는 전부 0(완전
  보호), B는 전부 0.417, C는 전부 0.75 — 채널 안에서 `sc_rate`가 완전히 균일해져
  공간 정보가 사라진다. `ours_intra_ch` 대비 48칸 전부가 다르다.

색은 `sc_rate` (0=보호/남색, 1=최대 억제/연노랑)을 나타내며 색맹 안전 팔레트(cividis)를
썼다. 주황 테두리는 각 경쟁 그룹의 1등을 표시한다(channel 패널은 채널 전체 테두리).

## 표시 방식 선택 (칸별 삼각형 vs 4번째 열 차이 맵)

`ours_layer` 패널은 `ours_intra_ch`와 8/48칸만 다르므로 칸별 주황 삼각형으로 정확히
어디가 달라졌는지 짚는 쪽이 정보량이 크다. 반면 `ours_inter_ch`는 사실상 전체(48/48)가
다르다 — 삼각형을 48개 다 찍으면 정보가 아니라 잡음이 된다. 이미 "채널 전체가 하나의
색으로 뭉개진다"는 사실 자체가 한눈에 보이므로, 이 패널은 문구 한 줄("채널 전체
균일값")로 대신했다. 두 패널에 같은 표시 방식을 억지로 맞추지 않고, 각 패널이 실제로
전달해야 하는 정보량에 맞춰 표시 방식을 달리했다.

## 실측 근거 (그림에는 수치를 넣지 않음, 참고용)

2026-09-21 확정: 같은 스파이크 예산에서 `ours_layer`가 `ours_intra_ch`보다 채널을
99개 더 죽인다(920 vs 828 / 4,736채널, 각 n=1). 즉 "층 전체 경쟁이 약한 채널을
통째로 지운다"는 이 그림의 메시지가 실측과 일치한다. 그림에서 ▲ 로 표시한
"약한 채널의 1등이 면제를 잃는 칸"이 정확히 그 기전이다. 이 수치는 캡션/본문에는
쓰되 그림 자체에는 넣지 않았다. n=1 이므로 이 숫자 자체는 아직 통계적으로 약하다 —
정본은 `eip-stats` 산출물을 따른다.
